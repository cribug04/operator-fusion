# 题一 · 残差加法与 RMSNorm 融合性能报告

对形状为 4 × 4096 的 BF16 输入执行 `residual = a + b` 和
`y = residual × rsqrt(mean(residual²) + eps) × w`。沿每行求均值，
四行共用长度为 4096 的权重，eps 取 1e-6。两版均返回 residual 和 y。

两步基线先写出残差，再从 DDR 读取残差执行 RMSNorm。融合版保留残差写回，
同时在向量缓存中直接使用刚完成的残差，省去归一化前的整块读回。

| 指标 | 两步基线 | 融合版 | 依据 |
| --- | ---: | ---: | --- |
| kernel 调用数 | 2 | 1 | 主机 Plan 与设备入口 |
| 算子 DDR 读写估算 | 172,032 B | 139,264 B | 逻辑张量字节数 |
| 主机 Plan DDR 工作区 | 32,768 B | 32,768 B | Plan 预留 |
| 主机 Plan SRAM 工作区 | 0 B | 0 B | Plan 预留 |
| 上板程序输入／输出缓冲区 | 73,728 B／65,536 B | 73,728 B／65,536 B | CalBin 清单 |
| 真机 VB 峰值 | 待测 | 待测 | 记录分配器或设备分析工具的口径 |
| 真机稳态中位数／P95 | 待测 | 待测 | 同板、同输入、同计时口径 |

每张矩阵 32,768 B，权重 8,192 B。融合读 a、b、w，写 residual、y，共
139,264 B。两步多读一次 residual，共 172,032 B。减少 32,768 B，即
19.0%。该估算只计逻辑张量读写，不含主机传输、设备事务开销和缓存影响。

主机端 6 项测试通过，覆盖作业数量、参数顺序、图形状和融合匹配边界。两版
CalBin 通过静态解析。上板用同一份输入覆盖普通值、整行抵消、全零、低幅值及
正负零权重，先验证残差和 RMSNorm，再对两版输出做字节比较。CPU 校验采用独立
公式，归一化输出暂用相对容差 3.5% 或绝对容差 0.002，待真机核验。

在本目录执行 `bash run_board.sh 0`，将 0 换成分配给团队的设备下标。
脚本保留设备状态、两版运行日志、原始输出和正确性日志。两版程序均使用一个
芯粒，入口配置两个核，0 号核执行算子。

正确性通过后，用现场 SDK 的计时接口各部署一次，预热后交替测量两版，记录
设备、固件、SDK 版本、编译耗时、加载耗时、预热次数、有效样本数、稳态中位数
和 P95。板端中位数加速比取两步版中位数除以融合版中位数。单次裸字节 CLI
耗时包括部署和主机 I/O，只能作为该调用流程的端到端数据。

当前两版的板端输出、实际 DDR 事务量和实测加速比均待现场记录。
