## Resize CPU 边界测试（2026-11-14 新增）

新增 `onboard/resize_reference.py`（形状通用参考库）与 `tests/test_resize_cpu_boundary.py`（19 项）。仍只验证 CPU 参考与地址算式，**不验证 NPU**。

三条互相独立的计算路径交叉对照：

| 路径 | 内容 | 独立性 |
| --- | --- | --- |
| `kernel_order` | 逐段复刻宏的三段展开（第 0 行 / 中间行 / 最后一行）与 he/ho 行内公式，f32 每步各舍一次 | 与 kernel 写法相同，用于预测设备输出 |
| `emulate_flat` | 用 kernel 里 `add` / `bind_strided` / `sub` 的地址算式在一维 bf16 内存上仿真 load/store，含通道分块 `xoff`；断言每个输出地址恰好写一次 | 检查四相位输出视图与通道块偏移的地址映射，不靠 numpy 切片 |
| `math_reference` + `to_bf16_bits_independent` | 坐标公式 `u=(o+0.5)/2-0.5`、clamp、权重矩阵，float64；bf16 舍入用 frexp 量化另写一份 | 与 kernel 写法、与原 reference.py 的位运算舍入都无共享代码 |

测试尺寸全部满足 kernel 源码里的 `const assert`：H、W ≥ 3；普通版 1 ≤ C ≤ 128；分块版 CC ≥ 32、CC % 32 == 0、C % CC == 0、W·CC·56 B ≤ 384 KiB。普通版用 (3,3,16)、(3,5,16)、(5,3,16)、(4,7,32)、(7,4,16)、(8,8,128)、(32,32,16)；分块版用 (3,3,64,32)、(4,5,96,32)、(5,4,128,64)、(6,6,256,64)、(3,7,320,32)、(32,32,256,64)。注意 C 不是 16 倍数、C < 16 的尺寸只是满足源码断言，**没有做过设备端编译**。

覆盖内容与结果（全部通过）：

- 常量：8 个常量 × 4 种形状，输出处处等于常量。
- 脉冲：内部脉冲的 16 个权重（0.75/0.25 组合）与手算一致；角点、边中点脉冲的 clamp 权重（1.0 / 0.75 / 0.25）与手算一致；3×3 全部 9 个位置；全部脉冲之和处处为 1。
- 渐变：水平、垂直、对角线性渐变的输出 = clamp 后的源坐标，逐位精确。
- 负值：负渐变三路一致；`resize(-x)` 位型 = `resize(x)` 翻符号位；混合符号随机与 1e-3..1e3 宽动态范围输入与独立公式 ≤ 1 ULP 且逐位相同率 ≥ 99.9%（实际为 100%）。
- 边缘 clamp：四角逐位等于输入角点；首/末输出行只依赖首/末输入行，首/末输出列同理；只有第 0 行非零时输出行 0/1/2/3+ 分别为 1 / 0.75 / 0.25 / 0。
- 通道分块：6 种 (H,W,C,CC) 的分块地址仿真与不分块 kernel 次序逐位一致；逐通道标识值不串块；块边界通道 (CC-1, CC, C-CC-1, C-1) 的脉冲不串到其他通道；CC=C、CC=32、不分块三种地址路径结果相同。
- 约束检查与 kernel 断言镜像；已提交两用例经地址仿真与独立公式复核逐位一致。

本轮**没有发现 kernel 源码或已存参考数据的错误**；唯一的失败是测试用例本身写错了一个“应当非法”的尺寸（320 可被 64 整除），已改正。
